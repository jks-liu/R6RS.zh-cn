\chapter{语言的变化}
\label{languagechangesappendix}

本章描述了自“修订$^5$报告”~\cite{R5RS}出版以来Scheme发生的大部分变化：

\begin{itemize}
\item 现在，Scheme源代码使用Unicode字符集。尤其，可被用作标识符的字符集被大大地扩展了。
\item 现在，标识符可以以{\cf ->}字符开始。
\item 现在，标识符和符号字面量是大小写敏感的。
\item 标识符和字符，布尔，数字对象和{\cf .}的表示必须被显式地区分。
\item 现在，{\cf \sharpsign}是定界符（delimiter）。
\item 字节向量字面量语法已被添加。
\item 匹配的中括号可以和小括号等价得使用。
\item 数据语法的简写{\cf \sharpsign{}'} (即{\cf syntax}), {\cf \sharpsign\backquote} (即{\cf quasisyntax}), {\cf \sharpsign{},} (即{\cf unsyntax}), and {\cf \sharpsign{},@} (即{\cf unsyntax-splicing})被添加；见第\ref{abbreviationsection}小节。
\item {\cf \sharpsign}不再可以用在数字的表示中替换数字。
\item 现在，数字对象的外部表示可以包括一个尾数宽度。
\item 非输和无限大的字面量被添加。
\item 现在，字符串和字符字面量可以使用各种转移序列。
\item 块注释和数据注释被添加。
\item 用作报告兼容的{\cf \sharpsign{}!r6rs}注释词汇语法被添加。
\item 现在，字符指定对应的Unicode标量值。
\item 现在，许多的程序和语言的句法形式是\rsixlibrary{base}库的一部分。一些过程和句法形式被转移到其它库中；见表~\ref{r5rsmovedfigure}。

\item 基本语言有下列新的过程和句法形式：{\cf letrec*}, {\cf let-values}, {\cf let*-\hp{}values}, {\cf real-valued?}, {\cf rational-valued?}, {\cf integer-valued?}, {\cf exact}, {\cf inexact}, {\cf finite?}, {\cf infinite?}, {\cf nan?}, {\cf div}, {\cf mod}, {\cf div-and-mod}, {\cf div0}, {\cf mod0}, {\cf div0-and-mod0}, {\cf exact-integer-sqrt}, {\cf boolean=?}, {\cf symbol=?}, {\cf string-for-each}, {\cf vector-map}, {\cf vector-\hp{}for-\hp{}each}, {\cf error}, {\cf assertion-violation}, {\cf assert}, {\cf call/cc}, {\cf identifier-syntax}。
\item 下列的过程被移除：{\cf char-\hp{}ready?}, {\cf transcript-on}, {\cf transcript-off}, {\cf load}。
\item 大小写不敏感的字符串比较（{\cf string-\hp{}ci=?}, {\cf string-\hp{}ci<?}, {\cf string-ci>?}, {\cf string-ci<=?}, {\cf string-ci>=?}）操作字符串大小写折叠（case-folded）的版本，而不是其对应的字符比较过程的简单的字典序。
\item 库被加到了语言当中。
\item 许多的标准库在一个单独的报告~\cite{R6RS-libraries}中被描述。
\item 许多“是一个错误”的情况现在有了预定义的或强制的行为。尤其，其中许多现在按照异常系统指定。
\item 现在，完整的数值塔是必须的。
\item 超越函数（transcendental functions）的语义被更加完整地指定。
\item 以零为底数的{\cf expt}的语义被改善
\item 在{\cf syntax-rules}形式中，一个{\cf\_}可以被用作取代关键词。
\item {\cf let-syntax}和{\cf letrec-syntax}不再为它们的内部引入一个新的环境。
\item 对于支持非数和无限大的实现，在这些值上的许多算术操作被指定和IEEE~754相一致。
\item 对于支持严格的-0.0的实现，关于-0.0的许多算术操作的语义被指定和IEEE~754相一致。
\item 现在，Scheme的实数对象有一个精确的零作为它们的虚部。
\item {\cf quasiquote}的规范被扩展了。现在，嵌套的quasiquotation可以正确地工作，且{\cf unquote}和{\cf unquote-splicing}被扩展到一些操作数上。
\item 现在，过程可以指向一个位置，或者也可以不指向一个位置。因此，在一些以前{\cf eqv?}有指定行为的地方，现在，其是未定义的。
\item {\cf quasiquote}结构的值的易变性在某种程度上被指定。
\item 现在，{\cf dynamic-wind}的\var{before}和\var{after}过程的动态环境是定义的。
\item 现在，只有副作用的各种表达式允许返回任意数量的值。
\item 宏扩展的顺序和语义被更加完整地指定。
\item 现在，内部定义按照{\cf letrec*}定义。
\item 程序结构和Scheme顶层环境的旧符号被顶层程序和库代替。
\item 指称语义（denotational semantics）被一个基于“修订$^5$报告”~\cite{R5RS}一个早期语义的操作语义（operational semantics）~\cite{mf:scheme-op-sem}取代。
\end{itemize}
